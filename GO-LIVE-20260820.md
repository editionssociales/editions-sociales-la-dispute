## 1. Ordre imposé

Le flip DNS **conditionne** le reste : tant que `editionssociales.fr` sert le WordPress OVH,
les URL de retour Stripe (`NEXT_PUBLIC_SITE_URL`) tombent sur un 404 WordPress.
Un donateur serait **débité sans confirmation**. Donc :

    flip DNS  →  certificat émis  →  SITE_INDEXABLE=1  →  webhook repointé  →  ANNONCE

**Ne pas annoncer la campagne avant que `https://editionssociales.fr/souscription` réponde 200 depuis Vercel.**
Prévoir le flip **le 19/08**, pas le matin du 20 : après la propagation, Vercel doit encore émettre le
certificat par ACME, fenêtre pendant laquelle le domaine répond « connexion non privée ».

## 3. Stripe — les 3 points que l'API n'expose pas

Compte **standard non-Connect** : `requirements`, `external_accounts` et les réglages d'e-mail ne sont
pas lisibles par la clé du compte (403 / champ absent). À contrôler **à l'œil, en mode Live** :

1. `dashboard.stripe.com/settings/emails` → **« Successful payments » doit être ON**.
   Le code ne pose jamais `receipt_email` : si c'est OFF, **aucun donateur ne reçoit rien**.
2. `dashboard.stripe.com/settings/payouts` → un IBAN doit être rattaché, sinon l'argent reste chez Stripe.
3. `dashboard.stripe.com/settings/update` → aucun bandeau de pièce justificative due.

  l'appariement clé/endpoint n'a jamais été exercé ;
