# src/lib

## Purpose

Unified product model and data layer: reads the Payload/Postgres catalogue (two fonds + boutique-only articles), exposes pure navigation and formatting, and hosts the native commerce engine (cart, quote, promo, checkout, order export).

## Ownership

- **Owns**: `RawBook` port + adapters (pg/memory), catalogue core (`catalogue-core`), catalogue facade + browse navigation, HTML sanitization, env layer, sellability rule, commerce engine (cart/quote/checkout/promo/order/export).
- **Does NOT own**: page rendering, UI components (except `cover.tsx`: domain rule, not layout), Payload collections, I/O orchestration in routes.

## Local Contracts

- Network modules: only `donations` (Stripe Search API, cached per-request via `cache()`) and `brevo` (write-side, never cached, degrades cleanly — `{ ok: false }` when `BREVO_API_KEY` absent) touch the network. `brevoConfigured()` is the SWITCH the whole site reads (page `/contact`, footer newsletter cell via a layout prop, `/admin/sante`): key absent ⇒ the manual e-mail fallback of `contact-address` replaces every form; posting the key restores everything with no code change.
- Purity: rest is pure; exceptions are back-office/commerce (server-only, Payload via Local API, no `cache()`): `catalogue-pg`, `commerce-source`, `order-source`, `highlight`, `rencontres`, `stripe`, `contreparties` — `getPayload({ config })` is memoized by Payload itself (process singleton), and for `order-source` a cached write would be a bug, not an optimization. `site-content` is the one exception to the exception: each exported getter (`getPagesLegales`, `getReglagesSite`, `getPageAPropos`, `getPageSouscription`, `getPageContact`) is wrapped in `cache()` (same pattern as `catalogue.ts`), because unlike the others it is called more than once per render (`getReglagesSite()` twice in `(site)/layout.tsx`) and the Payload singleton alone doesn't dedupe the `findGlobal` call itself. `contreparties.ts` reads `books` by slug (`getContrepartieBooksBySlugs`, resolution/display) and by id (`getContrepartieBooksByIds`, `souscription/merci` decoding `metadata.donLines` back to titles) — both `draft: true`, drafts included: contreparties may reference minimal/unpublished fiches, unlike the public catalogue's `PUBLIC_BOOKS_READ`. Not tested unitarily (same convention as `catalogue.ts`) — all pure logic (composition, selection resolution) stays in `contreparties-core.ts`.
- Type ownership: `SafeHtml` (only `sanitizeCms`), RawBook/CatalogueSource (ports), CommerceInfo (port-owned).
- `env.ts`: `DATABASE_URL` + `PAYLOAD_SECRET` REQUIRED at boot (Payload is the only source); the rest optional but shape-checked.
- URL codec: `catalogueHref`/`readFilters` (browse.ts) = unique encoder/decoder for filter URLs.
- `rencontres.ts`: reads the Payload `rencontres` collection (agenda, `/rencontres`) — `splitRencontres` (sort/split around today) is the pure, tested half; `getRencontres` is the I/O half, degrades to an empty agenda on failure like `highlight.ts`. Event days and "today" go through `isoDayParis` (format.ts) — Payload's `dayOnly` picker stores local midnight (22h/23h UTC the day before from France), so slicing the UTC ISO shifts the day; `parisMidnightUtc` (format.ts) is the inverse (day → instant), the boundary used by the admin filter chips.

## Work Guidance

- New catalogue data: extend `RawBook` and the pg mapper (`catalogue-pg-map`); never call `getPayload` outside the named modules above.
- `catalogue.ts` is the sole app entry point — a single tagged data-cache (`catalogue`, 24 h safety net, expired by the back-office hooks) feeds `getAllBooks` AND `getBook` (derived from the full set, never a per-book query); `browse.ts` wraps pure logic.
- **Single-source-of-truth rule**: domain rules live once in their module and are never re-inlined at call sites. `money.ts` owns the cents/euros conversion (`eurosToCents`/`centsToEuros`); `sellability.ts` owns stock/parution semantics (`assessSellability`); `nouveaute-book.ts` owns the Book→carousel mapping (`toNouveauteBooks`); `shipping-core.ts` owns the manifest-cart rule (`isManifestOnly`); `promo-core.ts` owns promo semantics (`isPromoExpired`, `normalizePromoCode`); `contact-address.ts` owns the public address AND every `mailto:` on the site (`CONTACT_EMAIL` + `buildMailto` — encodes subject/body, truncates the body under `MAILTO_MAX_LENGTH` on a word boundary rather than emitting a dead link). The address is a HARD constant, deliberately NOT env-overridable: it is the fallback for the day the mail chain is unprovisioned, and a configurable fallback disappears exactly when configuration is missing. `CONTACT_TO_EMAIL` (env) stays what it is — a transactional routing destination, never a published address; `video.ts` owns the YouTube URL → embed rule (`youTubeEmbedUrl`, null on anything unrecognized — never render a broken iframe); `site-content-core.ts` owns the contrepartie « ou » rule (a line starting with the word "ou" is an alternative to the previous one — parsed once for defaults AND back-office input, the renderer only reads `alternative`); `contreparties-core.ts` owns the STRUCTURED contrepartie composition (`CONTREPARTIES_2026`: ordered `inclus`/`choix` sections, items by product slug, `resolveContrepartieItems` resolving a donor selection into a deduplicated item list) — distinct from `site-content-core.ts`'s editorial "ou" text, consumed by DB resolution/shipping instead of page rendering; `cart-quote.ts` owns the full quote composition (`computeCartQuote` + `ShippingMethodLabel` for Orders — derived from actual shipping result, never coupon validity alone) AND the commande/précommande split (client 2026-08-20): the shipping tariff is resolved ONCE on the combined cart, then charged once per non-empty part (`normal`/`preorder`, ×1 homogeneous cart, ×2 mixed cart) — `checkout-core.ts:splitValidatedLines` only groups already-validated lines by `isPreorder`, it re-derives no business rule; `catalogue-core.ts:getFacets` owns facet order (alphabetical from `tally`) — the libellé chips of `catalogue-filters` render it as-is; the tiered « cases variables » view (`libelle-mosaic`, the only libellé view since the 25/07 arbitration) sorts its own LOCAL COPY by count desc — never mutate the facets array, never sort anywhere else; `mail-shell.ts` owns the shared HTML envelope of every transactional e-mail (doctype/`<title>`, hidden preheader, header monograms + wordmark, visible heading) — `order-mail.ts`/`donation-mail.ts` supply only their heading and body rows, never re-declare the DA constants (`PAPER`/`INK`/…) or the outer table markup; `catalogue.ts:getCatalogueBooks` (private) owns the goodies-out-of-catalogue rule (client 2026-08-20) — `getBooks`/`getFacets` (so `getNewReleases`/`catalogueView`, derived from both) filter to `origin: "catalogue"` through this single helper, never re-inlined; `getAllBooks` itself stays unfiltered (panier/checkout validate goodies lines too), and `getBoutiqueBooks` keeps its own symmetric `origin: "boutique"` filter for the boutique surfaces (`/boutique/[slug]`, panier suggestions, sitemap).
- **Commerce seams**: Payload I/O for the purchase path enters only via `commerce-source` (books facts + promo codes, read policy locked by `commerce-source.test.ts`) and `order-source` (Order lifecycle). Never widen `CommerceInfo` (port-owned), never inline `getPayload` in routes/actions.
